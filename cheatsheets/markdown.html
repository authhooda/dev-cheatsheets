Headings

Use the # symbol to create headings. More # symbols create smaller headings. 

# Heading 1

## Heading 2

### Heading 3

#### Heading 4

##### Heading 5

###### Heading 6

Code Blocks

Inline Code 

`const name = "Aryan";`

Fenced Code Block

Use three backticks around multi-line code. 

```javascript
const message = "Hello";

console.log(message);
```

Bash Example 

```bash
npm install
npm start
```

Python Example 

```python
name = "Aryan"

print(name)
```

Escaping Characters

Use a backslash when you want Markdown to display a special character instead of interpreting it.

HTML Inside Markdown

Many Markdown implementations allow HTML to be included directly in Markdown documents. 

<div>
    Custom HTML content
</div>

Support for specific HTML elements can vary between Markdown processors.

Collapsible Sections

GitHub supports HTML details elements in Markdown. 

<details>

<summary>Click to expand</summary>

Hidden content goes here.

</details>

HTML Comments

HTML comments can be used when your Markdown processor allows HTML. 

<!-- This comment will not normally appear on the page. -->

GitHub README Badges

Badges are commonly used in README files to show information such as build status, version or license.

![License](https://img.shields.io/badge/license-MIT-blue)

Recommended README Structure

Short description.

## Features

- Feature one
- Feature two

## Installation

Explain how to install the project.

## Usage

Explain how to use it.

## Configuration

Explain important configuration options.

## Contributing

Explain how others can contribute.

## License

Add the project license.

GitHub Markdown Tips

  • Use headings to organize long README files.
  • Use code blocks for commands and source code.
  • Use tables for structured information.
  • Use task lists for checklists.
  • Use links to connect documentation and resources.
  • Keep README files easy to scan.
  • Preview Markdown before committing documentation changes.
