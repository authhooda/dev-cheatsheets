HTTP Basics

HTTP stands for HyperText Transfer Protocol. It is the protocol commonly used for communication between clients and servers on the web.

A client sends an HTTP request and a server sends an HTTP response. 

Client
  |
  | HTTP Request
  v
Server
  |
  | HTTP Response
  v
Client

HTTPS

HTTPS is HTTP transported over a secure TLS connection. It helps protect data while it travels between client and server.

URL Structure

https://example.com:443/users?id=42#profile
  • https — protocol
  • example.com — host/domain
  • 443 — port
  • /users — path
  • ?id=42 — query string
  • #profile — fragment

HTTP Methods

Method Purpose Typical Use
GET Read data Fetch users
POST Create/submit data Create a user
PUT Replace a resource Replace user data
PATCH Partially update Change user email
DELETE Delete data Delete a user
HEAD Get headers only Check resource metadata
OPTIONS Discover supported options CORS preflight

HTTP Request

A request commonly contains a method, URL, headers and optionally a body. 

POST /api/users HTTP/1.1
Host: example.com
Content-Type: application/json
Authorization: Bearer TOKEN

{
  "name": "Aryan",
  "email": "aryan@example.com"
}

Request Parts

  • Method — what action to perform
  • Path — requested resource
  • Headers — metadata about the request
  • Body — optional data sent to the server

HTTP Response

HTTP/1.1 200 OK
Content-Type: application/json

{
  "id": 42,
  "name": "Aryan"
}

Response Parts

  • Status line — protocol version and status
  • Headers — response metadata
  • Body — optional response data

Status Codes

HTTP status codes are grouped into five major categories.

Range Category
1xx Informational
2xx Successful
3xx Redirection
4xx Client error
5xx Server error

Common Status Codes

Code Name Meaning
200 OK Request succeeded
201 Created Resource was created
204 No Content Successful response with no response body
301 Moved Permanently Resource has a permanent new URL
302 Found Temporary redirect
304 Not Modified Cached representation can be reused
400 Bad Request Request is invalid
401 Unauthorized Authentication is required or failed
403 Forbidden Server refuses the request
404 Not Found Resource was not found
405 Method Not Allowed Method is not supported for the resource
409 Conflict Request conflicts with current state
422 Unprocessable Content Request format is understood but data is invalid
429 Too Many Requests Rate limit has been exceeded
500 Internal Server Error Unexpected server-side failure
502 Bad Gateway Gateway received an invalid upstream response
503 Service Unavailable Server is temporarily unable to handle the request
504 Gateway Timeout Gateway did not receive a timely upstream response

Query Parameters

GET /users?page=2&limit=20&sort=name

Query parameters are commonly used to provide filtering, pagination, sorting or other optional request parameters. 

GET /products?category=books&minPrice=10

Path Parameters

GET /users/42
GET /products/1001

The value in the URL path commonly identifies a specific resource.

Cookies

Cookies are small pieces of data that a browser can store and send with requests. 

Set-Cookie: sessionId=abc123; Secure; HttpOnly

Common cookie attributes include:

  • Secure — send over secure connections
  • HttpOnly — prevents JavaScript from directly reading the cookie
  • SameSite — controls cross-site cookie behavior
  • Max-Age — specifies a lifetime
  • Expires — specifies an expiration date
  • Path — limits the request paths where the cookie is sent
  • Domain — controls the applicable domain

Caching

HTTP caching can reduce network requests and improve loading performance. 

Cache-Control: max-age=3600

Common Cache-Control Values

  • max-age — freshness lifetime in seconds
  • no-cache — requires validation before reuse
  • no-store — do not store the response
  • public — may be stored by shared caches
  • private — intended for a private cache

Authentication

Bearer Token

Authorization: Bearer YOUR_TOKEN

Basic Authentication

Authorization: Basic BASE64_USERNAME_PASSWORD

Never place sensitive credentials directly into URLs when a safer authentication mechanism is available.

CORS

CORS stands for Cross-Origin Resource Sharing. It controls whether a browser permits a web page from one origin to access resources from another origin. 

Access-Control-Allow-Origin: https://example.com

Common CORS Headers

  • Access-Control-Allow-Origin
  • Access-Control-Allow-Methods
  • Access-Control-Allow-Headers
  • Access-Control-Allow-Credentials

CORS Preflight

Browsers can send an OPTIONS request before certain cross-origin requests to determine whether the actual request is permitted. 

OPTIONS /api/users HTTP/1.1
Origin: https://example.com
Access-Control-Request-Method: POST
Access-Control-Request-Headers: Content-Type

JavaScript Fetch

fetch("/api/users")
    .then(response => response.json())
    .then(data => console.log(data));

POST Request

fetch("/api/users", {
    method: "POST",
    headers: {
        "Content-Type": "application/json"
    },
    body: JSON.stringify({
        name: "Aryan"
    })
});

cURL

GET

curl https://example.com

POST JSON

curl -X POST https://example.com/api/users \
  -H "Content-Type: application/json" \
  -d '{"name":"Aryan"}'

Show Response Headers

curl -i https://example.com

Browser DevTools

When troubleshooting HTTP requests in a browser, open DevTools and inspect the Network tab.

  • Request URL
  • Request method
  • Status code
  • Request headers
  • Response headers
  • Request payload
  • Response body
  • Cookies
  • Timing information

Common HTTP Troubleshooting

Problem Things to Check
404 URL, route, resource name and server configuration
401 Credentials, token and authentication configuration
403 Permissions, authorization and server access rules
405 HTTP method supported by the endpoint
429 Rate limits and request frequency
500 Server logs and application errors
502 Reverse proxy, gateway and upstream server
503 Server availability and service health
504 Gateway timeout and upstream response time
CORS error Origin and server CORS response headers

API Debugging Checklist

  1. Check the request URL.
  2. Check the HTTP method.
  3. Check the status code.
  4. Inspect request headers.
  5. Inspect the request body.
  6. Inspect response headers.
  7. Inspect the response body.
  8. Check authentication.
  9. Check CORS configuration for browser requests.
  10. Check server and application logs for server-side errors.
