Git Cheatsheet

Essential Git commands for repositories, commits, branches, remotes, merging, rebasing and everyday workflows.

Quick Reference

Command Purpose
git init Create a new Git repository
git clone URL Copy a remote repository
git status Show repository status
git add . Stage all changed files
git commit -m "message" Create a commit
git push Upload commits to a remote
git pull Download and integrate remote changes
git log View commit history

Git Basics

Git is a distributed version control system. It tracks changes to files and allows developers to work safely on different versions of a project.

Check Git Version

git --version

Configure Your Identity

git config --global user.name "Your Name"

git config --global user.email "you@example.com"

View Configuration

git config --list

Repositories

Create a New Repository

git init

Initializes the current folder as a Git repository.

Clone a Repository

git clone https://github.com/user/project.git

Clone Into a Specific Folder

git clone https://github.com/user/project.git my-project

Check Repository Status

git status

Basic Git Workflow

A typical Git workflow is:

  1. Edit files.
  2. Check the changes.
  3. Stage the changes.
  4. Create a commit.
  5. Push the commit to a remote repository.
git status

git add .

git commit -m "Add new feature"

git push

Staging Changes

Stage One File

git add index.html

Stage Multiple Files

git add index.html css/style.css

Stage Everything

git add .

Unstage a File

git restore --staged index.html

Commits

Create a Commit

git commit -m "Update homepage"

View Commit History

git log

Compact History

git log --oneline

Show a Specific Commit

git show COMMIT_ID

Modify the Most Recent Commit

git commit --amend -m "Updated message"

Viewing Changes

Unstaged Changes

git diff

Staged Changes

git diff --staged

Changes Between Commits

git diff COMMIT1 COMMIT2

Branches

List Branches

git branch

Create a Branch

git branch feature-login

Switch Branch

git switch feature-login

Create and Switch

git switch -c feature-login

Delete a Branch

git branch -d feature-login

Force Delete a Branch

git branch -D feature-login

Merging

Merging combines the changes from one branch into another branch.

Merge a Branch

git switch main

git merge feature-login

Abort a Merge

git merge --abort

After Resolving Conflicts

git add .
git commit

Remote Repositories

View Remotes

git remote -v

Add a Remote

git remote add origin https://github.com/user/project.git

Change Remote URL

git remote set-url origin https://github.com/user/project.git

Remove a Remote

git remote remove origin

Pushing Changes

Push Current Branch

git push

Push a Specific Branch

git push origin main

Push and Set Upstream

git push -u origin main

The -u option connects the local branch to the remote branch so future pushes can usually use simply git push.

Pull & Fetch

Pull Changes

git pull

Pull From a Specific Branch

git pull origin main

Fetch Remote Changes

git fetch

git fetch downloads information about remote changes without automatically merging them into your current branch.

Undoing Changes

Discard Uncommitted Changes in a File

git restore index.html

Unstage a File

git restore --staged index.html

Reset to Previous Commit

git reset HEAD~1

Hard Reset

git reset --hard HEAD~1

Be careful with --hard. It can permanently discard uncommitted changes.

Revert a Commit

git revert COMMIT_ID

Creates a new commit that reverses the changes introduced by an earlier commit.

Rebase

Rebasing moves or reapplies commits onto another base commit and can create a cleaner linear history.

Rebase Onto Main

git switch feature-login

git rebase main

Continue After Conflict Resolution

git add .
git rebase --continue

Abort Rebase

git rebase --abort

Git Stash

Stash temporarily stores uncommitted changes so you can work on something else.

Save Changes

git stash

Save With a Message

git stash push -m "Work in progress"

List Stashes

git stash list

Apply Latest Stash

git stash apply

Apply and Remove Latest Stash

git stash pop

Delete a Stash

git stash drop

Tags

Create a Tag

git tag v1.0.0

List Tags

git tag

Push a Tag

git push origin v1.0.0

Push All Tags

git push origin --tags

Common GitHub Workflow

A common workflow for contributing to a project: 

git clone https://github.com/user/project.git

cd project

git switch -c feature-name

# Make changes

git add .

git commit -m "Add feature"

git push -u origin feature-name

After pushing, a pull request can be opened on GitHub to propose merging the branch.

.gitignore

A .gitignore file tells Git which files or folders should not be tracked. 

node_modules/
.env
dist/
build/
*.log
.DS_Store

Example

project/
├── index.html
├── package.json
├── node_modules/
└── .gitignore

With node_modules/ in .gitignore, Git will ignore that folder.

Everyday Workflow

# Check what changed
git status

# See the actual changes
git diff

# Stage changes
git add .

# Create a commit
git commit -m "Describe the change"

# Get remote updates
git pull

# Upload your commits
git push

Common Problems

“Nothing to commit”

git status

Check whether your files actually changed and whether the changes were already committed.

Remote Not Configured

git remote -v

If no remote exists, add one: 

git remote add origin https://github.com/user/project.git

Push Rejected

git pull --rebase origin main
git push

Review the changes carefully if Git reports conflicts before continuing.

Important Git Rules

  • Commit small, logical changes.
  • Write clear commit messages.
  • Check git status frequently.
  • Pull remote changes when appropriate.
  • Do not commit passwords, API keys or secrets.
  • Use .gitignore for files that should not be tracked.
  • Be careful with destructive commands such as reset --hard.
  • Do not rewrite shared history unless the team workflow allows it.
