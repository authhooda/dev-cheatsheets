GitHub Basics

Git is a version control system. GitHub is a platform for hosting Git repositories and collaborating on software projects.

  • Repository — project storage.
  • Branch — independent line of development.
  • Commit — saved change in Git history.
  • Pull request — proposal to merge changes.
  • Issue — task, bug report or discussion.
  • Actions — automation and CI/CD.
  • Pages — hosting for static websites.

Create a Repository

  1. Sign in to GitHub.
  2. Select New repository.
  3. Enter a repository name.
  4. Choose public or private visibility.
  5. Optionally add a README.
  6. Create the repository.

A repository can contain source code, documentation, configuration files and other project files.

Clone a Repository

Clone using HTTPS 

git clone https://github.com/USERNAME/REPOSITORY.git

Enter the Repository 

cd REPOSITORY

Check the Remote 

git remote -v

Connect an Existing Local Project 

cd my-project

git init

git add .

git commit -m "Initial commit"

git branch -M main

git remote add origin https://github.com/USERNAME/REPOSITORY.git

git push -u origin main

This workflow connects an existing local project to a GitHub repository.

Branches

Create a Branch 

git switch -c feature-login

Push the Branch 

git push -u origin feature-login

List Branches 

git branch -a

Switch Branch 

git switch main

Pull Requests

A pull request lets you propose changes from one branch into another. It also provides a place for discussion, review and automated checks.

Typical Workflow 

git switch -c feature-navbar

git add .

git commit -m "Add navigation bar"

git push -u origin feature-navbar

After pushing the branch, open GitHub and create a pull request from the feature branch into the target branch.

Pull Request Steps

  1. Open the repository.
  2. Open the Pull requests tab.
  3. Select New pull request.
  4. Choose the source and target branches.
  5. Review the changed files.
  6. Add a title and description.
  7. Create the pull request.
  8. Review checks and feedback.
  9. Merge the pull request when appropriate.

Issues

GitHub Issues can be used to track bugs, tasks, feature requests and project discussions.

Useful Issue Information

  • Title — short description.
  • Description — details and context.
  • Labels — categorize the issue.
  • Assignees — people responsible for the work.
  • Milestones — group work toward a goal.

GitHub Actions

GitHub Actions can automatically run workflows when events such as pushes or pull requests occur.

Workflow files are normally stored inside: 

.github/workflows/

Example Workflow 

name: CI

on:
  push:
    branches:
      - main

jobs:

  test:

    runs-on: ubuntu-latest

    steps:

      - name: Checkout
        uses: actions/checkout@v4

      - name: Run command
        run: echo "Hello from GitHub Actions"

GitHub Pages

GitHub Pages can host static websites from a GitHub repository.

Typical Setup

  1. Push your website to a GitHub repository.
  2. Open the repository on GitHub.
  3. Go to Settings.
  4. Open Pages.
  5. Choose the deployment source.
  6. Select the branch and folder if required.
  7. Save the configuration.

Releases & Tags

Git tags can mark specific points in project history. GitHub Releases can provide release notes and downloadable release assets.

Create a Tag 

git tag v1.0.0

Push a Tag 

git push origin v1.0.0

List Tags 

git tag

Forks

A fork is a separate copy of a repository under another GitHub account or organization.

Typical Fork Workflow

  1. Fork the repository on GitHub.
  2. Clone your fork locally.
  3. Create a feature branch.
  4. Make and commit changes.
  5. Push the branch to your fork.
  6. Open a pull request to the original repository.

Collaboration Workflow

Start With the Latest Main Branch 

git switch main
git pull

Create Your Branch 

git switch -c feature-name

Save Your Work 

git add .
git commit -m "Describe the change"

Publish the Branch 

git push -u origin feature-name

Security Basics

  • Never commit passwords or API keys.
  • Use environment variables for secrets.
  • Review files before pushing them.
  • Use appropriate repository access controls.
  • Keep dependencies and workflows maintained.

Check What Will Be Committed 

git status

git diff --staged

Useful Git Commands

Command Purpose
git remote -v Show remote repository URLs
git fetch Download remote repository information
git pull Fetch and integrate remote changes
git push Upload local commits
git branch -a List local and remote branches
git log --oneline View compact commit history
git status Show the current repository status

Common Problems

Check Repository Status 

git status

Check Remote URL 

git remote -v

Change Remote URL 

git remote set-url origin https://github.com/USERNAME/REPOSITORY.git

Check Current Branch 

git branch --show-current

Pull Before Pushing 

git pull --rebase origin main

If Git reports conflicts, resolve the conflicts carefully before continuing.
